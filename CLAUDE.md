# CLAUDE.md

Working notes for AI coding assistants (Claude Code and others) on this repository. Humans are welcome to read
them: they are the short version of [CONTRIBUTING.md](CONTRIBUTING.md) and [docs/architecture.md](docs/architecture.md).

## What this is

cheminee is a paragliding cross-country flight planner in Python. Input: a DEM (ESRI ASCII grid) and the weather
of the day. Output: feasible routes (free distance, flat / FAI triangles, goal) with timing, climbs and speed to
fly, shown in a matplotlib GUI or a plotly 3D scene, or exported as a **flight package** (JSON) for the sister
app **vautour** (TypeScript, separate repository).

The physics is explained in [docs/model.md](docs/model.md). Read it before changing a formula.

## Commands

```bash
pip install -e ".[dev]"                                # once; CPU torch is enough
tar -xzf data/rasters_COP30_sample.tar.gz -C data/     # once; sample DEM -> data/output_hh.asc
pytest                                                 # 58 tests, ~15 s, no network
pytest tests/test_planner.py -k triangle               # one area
ruff check . && ruff format --check .                  # lint + format check (CI runs both)
ruff check --fix . && ruff format .                    # fix
cheminee plan data/output_hh.asc                       # quick end-to-end run, prints routes
cheminee export data/output_hh.asc --out /tmp/flight.json
cheminee serve data/output_hh.asc                      # web interface on http://127.0.0.1:8765
```

Set `MPLBACKEND=Agg` when running anything that draws without a display.

## Architecture rules (do not break)

- Layers: `domain/` ← `weather/`, `lift/` ← `planning/`, `training/` ← `viz/`, `export/`, `web/`, `cli.py`.
  Dependencies only point inwards. `domain/` and `weather/model.py` import nothing else from the package.
- The planner only sees the `LiftModel` protocol (`field(hour_local) -> (ny, nx) array in [0, 1]`) and a
  `Weather`. Choosing implementations happens only in `cli._flight_setup` / `cli.build_weather`.
- Heavy or optional imports stay local: `torch` only in `lift/neural.py` and `training/`; `plotly` only in
  `viz/scene3d.py`; HTTP only in `weather/openmeteo.fetch` (the `web/` server only listens on 127.0.0.1). Front-end
  libraries are vendored with their licence in `web/static/vendor/<name>-<version>/`, never loaded from a CDN.
  Importing `cheminee.planning` must not import torch.
- Network features must be computed by `lift/features.py` for both training and inference. Changing the feature
  list invalidates checkpoints (they are refused at load time): retrain `models/thermal_net.pt` in the same PR.
- `weather/openmeteo.py` keeps the pure conversion (`weather_from_payload`) apart from the network call (`fetch`),
  so tests run on saved answers (`tests/data/`).

## The flight package contract

`src/cheminee/export/flight_package.py` writes it; `schema/flight-package.v1.schema.json` defines it;
[docs/flight-package.md](docs/flight-package.md) documents it. vautour keeps a copy of the schema and a sample
package generated by this repository.

- Any change to the exported JSON must update the schema, the doc, `tests/test_export.py` and CHANGELOG.md in
  the same commit.
- Optional new key: stays version 1. Renamed / removed / re-meaning key: new `flight-package.v2.schema.json` and
  `FORMAT_VERSION = 2`. Never silently change the meaning of an existing key: phones in the field run old builds.
- Then sync vautour (sibling checkout): `cp schema/flight-package.v1.schema.json ../vautour/schema/` and
  `cheminee export data/output_hh.asc --out ../vautour/public/flight.json`, and open the matching vautour PR.
- Labels and enums in the package are English (`kind`, `aspect`); vautour translates them.
- `meta.attribution` must keep the Copernicus DEM notice, plus the Open-Meteo notice whenever a forecast was
  used. Do not remove them: the data licences require them.

## Conventions

- **Everything in English**: identifiers, docstrings, comments, log lines, exception messages, docs.
- Python ≥ 3.10, type hints on public functions, numpy-style vectorised code on grids (no Python loops over DEM
  cells). Ruff with line length 120 (`pyproject.toml`).
- Logs are plain `print()` lines with a short bracketed prefix: `[nodes]`, `[graph]`, `[search]`, `[export]`,
  `[train]`... Keep them one line, with numbers that help debugging (counts, ranges, timings).
- Units in names when ambiguous: `_m`, `_ms` (m/s), `_kmh`, `_deg`, `_s`, `_h`. Times are decimal local hours
  unless the name says UTC or solar.
- Local frame: x east, y north, metres, origin at the south-west corner of the DEM. `Terrain.z` keeps the raster
  convention (row 0 = north edge): convert with `Terrain.xy_to_rowcol` / `rowcol_to_xy`, never by hand.
- Wind directions are where the wind comes FROM in user-facing values (`wind_dir_deg`), and vectors point where
  the air goes inside the model (`W`). Check which one you have.
- New user-facing parameter: give it a default in `config.py` or `Weather`, a CLI option, and a line in the README
  tables.

## Tests

- Fixtures in `tests/conftest.py` build an analytical terrain (two ridges and a valley): fast and file-free.
  Prefer it over the sample DEM in unit tests.
- No test may touch the network. Forecast code is tested on `tests/data/openmeteo_digne_2026-11-15.json`.
- When fixing a bug, add the test that would have caught it.
- Planner results are deterministic for a given input: assert on structure and physical invariants (continuity
  of segments, closing rule, margins, monotonic time), not on exact kilometres, unless the test is a regression
  test that says so.

## Things to be careful about

- This is a **flight aid prototype**. Never present outputs as safe or validated; keep the status warning in the
  README. The shipped network is trained on synthetic tracks.
- IGC files are personal data. Never commit real tracks; `data/` is git-ignored except the sample DEM.
- Do not commit large binaries (> 5 MB). Generated HTML, PNG and JSON outputs are ignored by `.gitignore`.
- The Open-Meteo free API is non-commercial only; keep request counts low (`--pause` in `fetch-weather`).
- Do not add a dependency for something numpy/scipy already do; discuss new runtime dependencies in the PR.
